# 功能与页面

README 只保留产品概览和启动方式；这里按页面整理 RepoRadar 的具体能力。所有 AI 生成内容都会保留历史版本，不会覆盖旧报告。

## 雷达与发现

`/feed` 默认不铺仓库列表，而是先给「今天值得看的几件事」：

- **机会卡**：从维护周报的 Issue/依赖风险、接入建议和关注代理命中里挑最多 3 条，带「为什么给你看」的证据和下一步入口；
- **隐藏宝石**：现场搜索小而活跃的项目（50–5000 stars、近 3 年创建、近 120 天有推送），排除大厂官方仓库、awesome 清单、教程和模板；支持「换一批」；
- **不感兴趣**：选择原因（太宽泛 / 又是官方库 / 不是我的栈 / 早知道 / 其他），雷达会记住并收紧后续筛选；
- **工具库**：标签分组、筛选、简报和 release 更新都保留在这个标签下；顶部还可以切换「精选 / 工具库 / 收藏」。

雷达顶部支持「综合 / 补项目 / 换工具 / 找灵感 / 看新东西」五种模式，并根据维护项目生成轻量的「雷达人格」。模式会保存到用户偏好；展示过的隐藏宝石进入 7 天冷却。「分享雷达」会生成无需登录的只读快照。

工具库卡片的「为什么是这个分数」会展开质量、新鲜度、增速、个人匹配和反馈/订阅的贡献；计算细节和默认权重见 [SCORING.md](SCORING.md)。

趋势页 `/trends` 基于已收录项目的 star 增速、主题分布和 release 事件。

## AI 搭档

`/workbench/copilot` 是懂当前上下文的项目搭档：

- 读取维护项目、最新维护周报、接入建议、关注代理和历史生成记录；
- 可以问「这周先做什么」「我的项目最该补什么」「帮我从接入建议里挑一个」；
- 回答会引用具体项目、依赖、Issue 和候选，不会声称已经执行代码或开 PR；
- 对话持久化，支持多会话、新建和删除；
- 快捷动作可以直接生成维护周报或接入建议。

对话走页面内 API，不锁导航；需要长任务的报告生成仍然走后台队列。

## 维护工作台

`/workbench/maintain` 把维护中项目的三件事合成一张周报：

- **健康度**：测试、CI、Issue/PR 积压、维护活跃度，以及 3–5 条本周建议动作；
- **依赖升级**：读取依赖清单和 lockfile（package-lock / pnpm / yarn / poetry / go / cargo），按实际安装版本查询 npm / PyPI / Go / crates.io 最新版本和 OSV 安全公告，标出风险，并尝试读取候选仓库的最新 release notes；
- **Issue / PR 待办**：按「现在 / 本周 / 稍后」分组，给出处理建议和回复草稿。

生成结果可以复制成维护任务书；Issue 待办还可以继续生成「修复方案」，包含可能涉及的文件、实现步骤、测试、风险和验收标准。

修复方案页可以点「生成修复补丁」：

- 读取 Issue、项目上下文和最多 8 个相关文件，让模型输出 `git apply` 可用的 unified diff；
- 在临时克隆里检查补丁能否应用，再把构建/测试放进 Docker 沙箱执行（资源、进程数、权限受限）；
- 结果保存为可回看的补丁版本，显示改动文件、构建状态和完整日志，可复制或下载 `.patch`；
- 不自动提交、推送、创建 PR 或关闭 Issue，需要人工审阅后执行。

依赖项可以点「生成升级补丁」：worker 在 Docker 沙箱里执行对应包管理器的升级命令（npm / pnpm / yarn / Go / Cargo；Python requirements 直接改版本），再跑构建或测试，最后返回包含 lockfile 的完整 diff。构建失败时仍保留补丁和日志。

## 接入建议

`/workbench/integrations` 以正在维护的项目为起点，找「当前没有、可以接入」或「已有、可以优化」的开源项目：

- 复制出的 Markdown 任务书包含项目摘要、能力缺口、候选仓库、选择理由、参考步骤和给代码 AI 的执行约束；
- 可以直接粘贴给 Claude Code、Cursor 等代码 AI，让它在目标项目里核实候选并执行接入；
- 任务书会要求 AI 先读项目、核实许可证与 API、只改目标项目、补测试并运行现有检查；
- 每条建议可以标记「已接入 / 不感兴趣」；已处理建议可以继续填写执行记录（PR、commit、安装版本或备注）；
- 下一次生成时，已拒绝的候选会被后端强制过滤，已采纳的方向会作为偏好参考。

建议库的接入标签可以在「按库查看」和「按维护项目」之间切换；按项目查看时会汇总该项目的历史未处理建议，可以一键复制给 AI，也可以只重新生成这一个库的接入建议。

## 相似项目对比

在维护工作台顶部、接入页项目列表或维护周报的项目卡片上都能打开「相似项目对比」，也可以直接访问 `/workbench/maintain/similar`：

- 不需要先生成周报，直接列出维护项目；
- 从项目描述和 README 提取领域关键词，不只依赖 GitHub topics；
- 从已收录候选和 GitHub 现场搜索中找出相似项目；
- 让模型对比双方优劣、目标项目应保留的优势、可以借鉴的具体设计，以及直接照搬的风险；
- 结果保存在历史报告中，也可以复制成给代码 AI 的参考任务书。

相似度是参考信号，不是结论；没有同赛道项目时会明确提示「主要作为工程实践参考」。

## 选型对比与 Issue 修复方案

接入报告里的项目卡片支持「对比候选」。系统读取目标项目和候选的 README / 依赖，输出适配度、优势、弱点、迁移成本、推荐项和验证步骤，并可复制成对比任务书。迁移成本是初步估算，替换前应先用小范围 spike 验证。

`/issue-plan` 可以为单个 Issue 生成修复方案和任务书；它只做规划，不会自动改代码、提交或开 PR。

## 关注代理

`/workbench/watch` 支持用一句话描述长期关注的项目，例如「MIT、TypeScript、能做 agent 长期记忆、最近三个月有 release」。

- AI 在已收录候选池里判断匹配度；
- 有 GitHub 授权时提取关键词现场搜索扩大候选；
- 给出理由并写入通知，不需要拆成 topic / 语言规则。

## 技术周报

`/workbench/issue` 生成技术周报选题和草稿。可以只用真实 release + 主题聚类证据包，也可以配置模型后直接生成完整 Markdown / HTML 草稿。

- 模型只输出结构化 JSON（主题、条目、行动），Markdown/HTML 渲染和校验在本地完成；
- 主题和忽略项里引用的仓库必须出现在证据中，否则会被自动丢弃，防止编造项目；
- 个别条目格式不合格时会被跳过而不是让整份草稿失败；
- 版本号和日期仍依赖模型忠实引用证据，发布前建议人工复核。

样刊在 [docs/issues/](issues/)，可以用 `pnpm radar issue` 生成新的证据包。

## 建议库与历史

`/library` 把所有 AI 生成内容按库或条目汇总：

- 接入推荐、关注命中、维护待办、选型对比和曝光优化各自显示出现次数、涉及项目、已接入、不感兴趣和待处理；
- 历史报告可以按 `?report=` / `?draft=` / `?plan=` 回看具体版本；
- 接入报告会记录本次候选池，对比报告会记录本次候选，方便确认结论基于什么；
- 历史报告标签支持分页；导出 JSON 默认是索引元数据，`/api/history/export?full=1` 会包含完整报告正文、周报 HTML、补丁和周报记录。

雷达、接入建议、维护待办、关注代理和隐藏宝石都支持「已接入 / 已完成 / 不感兴趣」状态；标记后不会再出现在后续推荐里，也不会被复制给代码 AI 的接入任务书。依赖完成状态绑定到具体目标版本，新的大版本出现时会重新出现。

## 后台 AI 任务

接入、维护周报、技术周报、曝光优化、选型对比、修复方案和关注匹配都不阻塞页面：

- 点击生成后创建持久化任务并立即跳到 `/tasks`；
- 任务在后台并行执行，期间可以正常浏览其他页面；
- 导航栏「任务」显示运行中的数量，任务中心显示进度、错误和结果入口；
- 完成后结果进入历史记录，也可以通过收件箱打开；
- 支持取消、失败/取消后手动重试、失败自动重试一次、10 分钟执行超时和 15 分钟心跳回收；
- 同一用户最多同时运行 2 个任务，其余排队；
- 设置页显示近 30 天的模型调用次数和 token 用量。

默认 Web 进程也会立即执行任务；生产环境建议设置 `RADAR_INLINE_JOBS=0`，只让独立 worker 执行：

```bash
pnpm worker
```

worker 会处理 `ai_jobs` 队列、恢复心跳超时的任务，并执行定时工作：每 15 分钟同步 GitHub 动态和关注的 release，每周为开启「每周精选」的用户生成摘要，持续投递邮件和浏览器推送。

## 收件箱与 GitHub 动态

`/inbox` 支持按「全部 / GitHub / AI 工作 / 版本 / 系统」分类、只看未读、单条「标记已读」和「全部标记已读」。

- 进入收件箱时，如果距离上次同步超过 6 小时，会自动排一个后台任务检查维护中仓库的 GitHub 动态；
- 新 star、fork、打开的 Issue / PR、发布的 release；
- 第一次同步只建立基线，不补发历史动态；
- 之后的动态来自仓库 events API 最近 30 条，忽略自己触发的操作；
- 应用打开时每 5 分钟触发一次轻量心跳，实际同步间隔约 15 分钟；
- 可以随时点「同步 GitHub 动态」手动触发；
- 在设置页可以分别关闭 star / fork / Issue / PR / release 通知。

没有配置 Webhook 时，GitHub 动态是轮询，通知会有延迟；Webhook 配置见 [OPERATIONS.md](OPERATIONS.md)。

## 仓库管理与曝光优化

`/repos` 支持选择一个或多个仓库后批量操作：

- **批量新建**：一次输入最多 10 个仓库名，共用描述、可见性、`.gitignore` 与许可证模板；
- **批量修改**：统一改描述、可见性（公开/私有）或归档状态；也可以单仓改名；
- **批量删除**：需要勾选确认，删除后不可恢复。

`/repos/[owner]/[name]/optimize` 从定位清晰度、搜索关键词、README 首屏、差异化和信任信号五个维度给仓库做可发现性体检：

- 给出新的仓库描述、Topics、README 首屏建议和按影响排序的执行动作；
- 确认后可以直接把描述和 Topics 写回 GitHub；README 不会自动修改；
- 私有仓库会提示「不会被 GitHub 搜索发现」，建议先评估是否公开。

## MCP server

RepoRadar 可以作为 MCP server 接入 Claude Code、Cursor、X-Code 等 agent：

```bash
pnpm radar mcp        # stdio 传输
```

在 MCP 客户端里配置（路径换成你的项目路径）：

```json
{
  "mcpServers": {
    "repo-radar": {
      "command": "node",
      "args": ["--import", "tsx", "/absolute/path/to/repo-radar/apps/worker/src/mcp-server.ts"],
      "env": { "RADAR_MCP_USER": "你的 GitHub 登录名" }
    }
  }
}
```

提供的工具：

| 工具 | 作用 |
| --- | --- |
| `search_repos` | 按关键词 / topic / 语言搜索已富化项目 |
| `get_recommendations` | 基于画像、反馈和订阅返回个性化推荐 |
| `get_digest` | 生成 Markdown 摘要 |
| `get_repo` | 仓库摘要与最近一次验证结果 |
| `record_feedback` | 写入收藏 / 不感兴趣 |
| `add_subscription` | 添加 topic / language / author / release 订阅 |
| `list_rising` | 近 7 天增速最快的项目 |
| `list_release_updates` | 关注仓库的最新 release |
| `get_recommendation_library` | 按库/条目汇总历史建议 |
| `get_pending_work` | 返回未处理的接入建议、维护待办和关注命中 |

`RADAR_MCP_USER` 用于给没有显式传 `login` 的工具提供默认用户。

## 摘要与订阅

- **反馈闭环**：feed 卡片上的「收藏 / 不感兴趣」写入 `feedback` 表。收藏会提升相关 topic 的权重并让仓库略微靠前；不感兴趣会立即隐藏该仓库，并把 topic 权重调低。
- **订阅规则**：在设置页或通过 MCP 添加 topic / language / author / release 订阅。前三类提升排序（单条最多 +0.1，总计上限 +0.2）；release 订阅用于追踪版本更新。
- **版本更新**：`pnpm radar releases` 检查所有 release 订阅仓库的最新版本并写入 `release_events`，feed 顶部展示「关注项目的更新」。
- **多样性约束**：排序后按 topic 和语言做软配额（默认每个 topic 最多 2 个、单语言不超过 60%），候选不足时自动放宽。
- **加速度雷达**：`pnpm radar rising --limit=10` 按近 7 天 star 相对增速排序，feed 顶部也会展示前 3 个「正在起飞」项目。需要至少 7 天快照历史。

摘要命令：

```bash
pnpm radar digest --user=demo --limit=10          # 打印 Markdown
pnpm radar digest --user=demo --format=html --out=/tmp/digest.html
pnpm radar digest --all --send                    # 通过 SMTP 发给所有有画像的用户
```
